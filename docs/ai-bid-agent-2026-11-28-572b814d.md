# AI-Bid-Agent 前端界面评审与两套整改方案（2026-11-28）

## 背景

对象：`AI-Bid-Agent` 的 Vue 3 + Vite 前端（`frontend/src/App.vue` 517 行，`frontend/src/style.css` 约 841 行，ECharts 按需注册见 `frontend/src/echarts.ts`）。用户的体感是「不丑，但哪儿都不舒服」，要求单独锐评前端。本文档记录诊断与两套可选改法，供后续实施或复评；同日后端/安全/交付层评审见文档 `55feed62-606f-4f0e-9a79-6abc2b9add60`（其 P2-2 只有一句前端结论，未展开）。

## 诊断结论：问题是「没有主次」

样式表里 45 个色值、9 档字号、8 种圆角、84 处手填的 padding/margin 叠加，更像手工调参的化石而非风格系统：眼睛每隔一百像素就要重新适应一套规则，所以一直找不到落点。

## 六个难受的来源（按体感排序）

1. **背景抢戏**：`bg.jpg` 是一张 2047×1152 的 CAD 平面图，body 上压 82~90% 白纱并加 `fixed`（`frontend/src/style.css:27-34`）。1440 屏上内容宽 1100，两侧各 170，加 16px 内边距后每侧实际露出约 186px 图纸，正好落在余光里；细线被白纱压成灰雾，纸固定、内容滚动，滚动时像在纸上打滑。处理：删图，底色回 `#f6f7f9`；真要纸感用 2~3% 噪点或极淡 `repeating-linear-gradient`，不要整张图。
2. **头太重**：最多 9 个状态药丸（真实抓取、演示模式、解析器、站点、指纹、定时、邮件、飞书、钉钉）+ 3 个按钮 + 6 段流程条（`frontend/src/App.vue:271-309`）。首屏两百来像素全在讲系统自己，唯一要人干活的输入框被压到第二屏；不可恢复的「清空指纹」还和状态药丸并排挂在品牌区。改：状态只留 3 个（后端、模型、推送），其余进「设置」抽屉；流程条删掉或压成一行 12px 灰字。
3. **六张同权重卡**：输入、趋势、意图、结果、任务、文档全是 `.card`——18/22 内边距、12px 圆角、shadow-sm、hover 抬阴影、挂载时 rise（`frontend/src/style.css:187-217`）。滚到哪屏重量都一样。改：白卡只留给「输入」与「结果」，趋势、任务、文档改为无边框分区（小标题 + 分隔线）。
4. **状态三套画法**：头部半透明白边药丸、表格实色 `.pill2`、KPI 左侧色条加数字变色（`frontend/src/style.css:751-785`）；语义色里还混进 Tailwind 薄荷绿 `#a7f3c4`、`#fde68a`，与自有 `--good #1a7f37` 不同源。收成一个 `.tag`：ok / warn / muted 三档，KPI 只靠数字颜色。
5. **尺度不成系统**：字号 11/12/12.5/13/14/15/17/21/26 九档（12.5 是半像素调参化石）；圆角 2/4/6/8/9/10/12/999 八种，8/9/10/12 肉眼难分。收敛为字号 12/13/14/18/26、圆角 4/8/999、间距走 8 的倍数。
6. **假交互**：`.card:hover` 抬阴影但点不动；复选框是浏览器原生控件，与自定义 textarea 不同源；清指纹弹原生 `confirm`（`frontend/src/App.vue:213`）；按钮与芯片都没有 `:focus-visible`。补一条统一 2px 外描边焦点环。

## 三个具体 bug

- **KPI 落单**：模板有 5 个 `.kpi`（抓取/新增/去重/正文已补/本轮条目），网格写 `repeat(4, 1fr)`（`frontend/src/style.css:478-483`），第 5 个孤零零挂在第二行 25%。改 5 列，或把「本轮条目」并进「抓取」。
- **图表从第二次执行起空白（代码路径推断，未实机复现）**：`doRun` 先把 `result` 置 null（`frontend/src/App.vue:184`），带 `v-if` 的图表 DOM 被卸载；`donutIns/barIns` 未 dispose，`renderCharts` 写成 `donutIns || init(...)`（`frontend/src/App.vue:84-86`），于是复用绑在已卸载节点上的旧实例，setOption 画在空气里。改：渲染前先 dispose 再 init，或改用 `v-show`。
- **报错在视野外**：`error` 渲染在输入卡内部（`frontend/src/App.vue:336`），失败时人正看着结果区。提示跟随结果区，并加 `aria-live="polite"`。

## 方案 A：去噪（约半天，只动 style.css 加三处 bug）

删 body 双背景与 bg.jpg 引用；masthead 二选一（全宽出血，或白底加 1px 下边线），去掉渐变与 `shadow-lg`；颜色砍成 1 主色 + 5 灰阶 + 3 语义色；圆角只留 4/8/999；药丸合成一套、删 `.pill2`；去掉 `.card` 的 hover 抬升与 rise；KPI 改 5 列、图表先 dispose、错误挪位。预期色值从 45 降到约 9、圆角从 8 种降到 3 种、头部高度从约 200px 降到 90px 以内，灰雾感与模板感降一大半。

## 方案 B：重排（1~2 天，拆组件）

顶栏 64px（标题 + 3 状态 + 设置抽屉）；主体两栏 `340px | 1fr`，左边输入、右边结果，空态显示最近一次；结果区顺序改为摘要结论 → KPI → 明细表 → 图表折叠（对「要不要投」这类判断，标题与正文的决策价值高于环图和柱图）；趋势、任务、文档收进右栏底部折叠；拆 11 个组件，`App.vue` 只留编排；三档断点；执行完 `scrollIntoView` 到结果标题。

## 状态与约束

- 截至评审时用户尚未在 A / B / 先别动 之间选择；未获选择前不改动任何前端文件。
- 本机未能渲染页面：本会话沙箱拒绝 Playwright 驱动与 docker API（见同日父会话记录），因此视觉结论来自 CSS、`App.vue` 模板与 bg.jpg 本身的静态推断；图表空白 bug 同为代码路径推断。需要 1440 宽整页截图或实机复核才能逐点确认。
- 评审的取舍依据：保留现有信息架构与工程实现，优先级是「先让人一眼看到该看的东西」，而不是换一套视觉主题。
