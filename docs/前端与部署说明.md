# 前端与部署决策说明

回答三个问题：前端补了什么、框架为什么选Vue不选React、nginx和docker要不要用。最后给出三种运行形态与验证状态。

## 一、现状：补了什么

此前交付确实全是后端（FastAPI＋Swagger文档页）。现已补齐**Vue 3.5＋Vite 6＋TypeScript 5.6单页仪表盘**，位于`frontend/`：

| 区块 | 内容 | 对应后端 |
|---|---|---|
| 状态栏 | MOCK徽章、解析器、站点数、指纹数、定时任务数、清空指纹 | `/api/health`、`/api/fingerprints/clear` |
| 一句话需求 | 输入框＋3个示例短语、「仅解析意图」「执行全链路」、两个开关 | `/api/intent/parse`、`/api/pipeline/run` |
| 意图解析 | 关键词/区域/时间范围/定时cron/解析器/指定站点 | 同上 |
| 执行结果 | 抓取/新增/去重统计卡、条目表（标题可点、摘要折叠、新增/重复徽章）、warnings | `/api/pipeline/run` |
| 定时任务 | 任务表＋下次执行时间＋删除 | `/api/tasks`、`/api/tasks/{id}` |
| 已生成文档 | 文件表＋在线下载 | `/api/files` |

**运行形态（演示默认）**：`npm run build`产出`frontend/dist`，后端`app/main.py`把它挂载在`/`——uvicorn单进程同源直出页面＋API，`run.ps1`一条命令起全套，浏览器打开`http://127.0.0.1:8000/`即用。API路由先注册、静态挂载兜底，`/api`、`/docs`不受影响。

前端代码结构刻意保持薄：`src/types.ts`（接口形状，与`app/models.py`的`to_dict()`一一对应）、`src/api.ts`（统一解包/报错）、`src/App.vue`（全部视图与状态）、`src/style.css`。无状态库、无路由——单页仪表盘不需要，等页面多了再加vue-router。

## 二、框架：为什么选Vue，不选React

| 维度 | Vue 3 | React 18 |
|---|---|---|
| **你的审查成本** | 你有Vue语法学习基础（此前交付过Vue基础讲解），模板＋组合式API你能直接读懂、自己改 | 你零接触，hooks规则、闭包陷阱、状态库选型全是新心智负担 |
| **项目形态匹配** | 单页仪表盘、无复杂状态流：一个`ref/reactive`＋props直通 | 单页场景下React的优势（生态选型自由、大团队协作规范）发挥不出来 |
| **中文生态** | 中文文档一等公民，国内政企/招标采购类前端Vue占比高，答辩讲解评委熟悉 | 文档以英文为主 |
| **TypeScript** | 两边支持程度相当，无差别 | 同左 |

**结论：Vue 3＋Vite＋TS**。决定性因素是第一条——vibe coding的前提是你能审查AI产出的每一行，这条对你而言Vue完胜。

## 三、nginx：要用吗

**结论：本机演示阶段不用；部署到服务器对外时用，配置已备好（`deploy/nginx.conf`）。**

nginx的职责是：静态资源高效服务（sendfile、gzip、缓存头）、反向代理＋TLS/HTTPS终结、并发限流、隐藏后端端口形成安全层。

- **现在不用的理由**：演示形态里uvicorn已经同源直出页面，功能完全覆盖；多加一个nginx＝多一个进程、多一份配置、多一个排障对象，答辩现场便携性和「一条命令起全套」的价值远大于生产级特性。本机实测也没有nginx环境。
- **将来什么时候用**：部署到云服务器对外提供访问、需要HTTPS、需要真实并发与缓存、后端要开多worker时。届时`deploy/nginx.conf`配合`docker-compose.yml`（或裸机）直接可用：静态走nginx、`/api/`反代到uvicorn。
- **为什么不反过来**（nginx在前不是教条）：它解决的是「对外服务」的问题，你现在没有这个问题。

## 四、docker：要用吗

**结论：开发与演示阶段不用；跨机器交付/部署时用，配置已备好（`deploy/Dockerfile`＋`deploy/docker-compose.yml`）。**

docker的职责是环境可复现——把Python版本、依赖、配置打包成镜像，做到「评委/队友拿到就能跑」，消除「在我机器上是好的」。

- **现在不用的理由**：①本机实测无Docker环境（`docker --version`缺失，Windows上装Docker Desktop还要WSL2，内存开销不小）；②演示闭环只在你自己机器上，venv＋run.ps1已经把环境约束死了；③不验证就交付的Dockerfile是埋雷——所以deploy/下的文件全部明确标注「未在本机验证」，启用前先跑一遍。
- **将来什么时候用**：把项目交给评委、队友或部署到服务器时。compose拉起两个服务：`app`（uvicorn）＋`nginx`（静态＋反代），环境零手工配置。

## 五、三种运行形态对照

| 形态 | 命令 | 组成 | 适用场景 |
|---|---|---|---|
| 前端开发 | `cd frontend && npm run dev`（:5173，/api自动代理到8000）＋另开`run.ps1` | vite热更新 | 改前端代码 |
| **本机演示（当前默认）** | `.\run.ps1`，打开`http://127.0.0.1:8000/` | uvicorn单进程：API＋静态同源 | 答辩、自用 |
| 服务器部署 | `cd frontend && npm run build` → `docker compose up` | nginx(80)＋uvicorn(8000，容器内) | 对外服务、交付他人 |
