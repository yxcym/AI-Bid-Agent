# AI-Bid-Agent 详设文档

v1骨架版配套设计说明。读者先读README再读本文。

## 1. 总体结构

```
AI-Bid-Agent/
├── app/
│   ├── main.py            # FastAPI装配 + lifespan启动/停止 + 全局异常
│   ├── models.py          # 全局4个数据类（ParsedIntent/RawNotice/Notice/PipelineResult）
│   ├── config.py          # config.yaml -> pydantic强类型
│   ├── common/errors.py   # BizException(message, status_code)
│   ├── intent/
│   │   ├── base.py        # IntentParser协议
│   │   ├── rule_parser.py # 正则规则解析（默认）
│   │   └── llm_parser.py  # 大模型解析（预留，失败自动回退rule）
│   ├── crawler/
│   │   ├── base.py        # CrawlerClient协议 + LoginRequiredError
│   │   ├── mock_client.py # mock数据（含广告噪声、刻意重复条目）
│   │   ├── http_client.py # httpx+BeautifulSoup真实抓取
│   │   └── registry.py    # mock/http装配开关
│   ├── pipeline/
│   │   ├── cleaner.py     # 去广告/空白归一/截断/MD5指纹
│   │   ├── dedup.py       # SQLite指纹表（is_new/save/clear）
│   │   └── service.py     # 七步编排
│   ├── docx_gen/generator.py  # python-docx版式
│   ├── push/emailer.py    # SMTP邮件推送（Word附件＋纯文本/HTML双摘要）
│   ├── schedule/scheduler.py  # APScheduler封装，标准cron映射
│   └── api/routes.py      # 薄路由层
├── config/config.yaml     # 站点清单、mock开关、字体、输出目录、推送开关
├── config/secrets.yaml    # 本地密钥覆盖层（gitignore，非必填）
├── requirements.txt
└── run.ps1                # 一键启动
```

模块边界原则：**每步的具体实现都在各自包里，service.py只串流程**。换解析器/抓取器/文档样式，编排层零改动。

## 2. 数据流

```
用户原话(str)
  → ParsedIntent      意图解析：keyword/region/时间范围/cron/sites/parser名
  → [RawNotice]       抓取：source/title/url/publish_date/content/need_login
  → Notice            清洗：剥广告、截断、fingerprint=MD5(标题+归一化URL)[:16]
  → 去重              新指纹入库+is_new=True；旧指纹is_new=False
  → Word              仅新增条目 → output/{query}_{yyyyMMddHHmm}.docx
  → cron注册          仅当原话带频率（如“每天9:00”→ 0 9 * * *）
```

### 2.1 意图解析（rule_parser.py）

- **频率**：支持每天N点/每周N/N点/每月N号N点/每小时；上午下午晚上自动换算12小时制；输出标准五段cron
- **时间**：最近N月/周/天、上个月、本月、本周、今天；缺省最近90天；中文数字（“三”）支持
- **区域**：省级＋主要地级市词典，最长匹配，连带吃掉“市/省/区域/地区”后缀防止残字污染关键词
- **关键词**：先剥噪声词（帮我/一下/发送给我…），再截断锚点词（招标信息/采购公告…）之前的部分，取末段、限8字
- **站点点名**：用户原话含站点名或域名主体时只抓该站，否则抓全部启用站点

已知弱点（有意留给LLM解析器）：同义表达（“昨天”/“上周五”）、无锚点的口语、多主题并列。

### 2.2 清洗与指纹（cleaner.py）

- 广告剔除三级：整行命中【广告/友情链接/版权所有/ICP备…】→整行丢；单行夹广告句 →按句号切段丢句；HTML残渣（script/style/标签）→先剥
- 正文超`doc.max_chars_per_item`（默认600）截断并标注“（原文过长，已截断）”
- 指纹＝MD5(标题＋“|”＋URL去query/锚点、转小写)[:16]。**URL必须归一化**：否则utm_source、时间戳、随机id会让同一篇每轮都算新的，增量语义直接失效

### 2.3 去重（dedup.py）

SQLite单表`bid_fingerprint(fingerprint PRIMARY KEY, title, url, source, first_seen)`。`is_new`→`save`在service里成对出现，无事务窗口。演示增量语义用`POST /api/fingerprints/clear`清库。

### 2.4 Word版式（docx_gen/generator.py）

- **中英分字体**：Normal样式与每个run都同时设`w:ascii/hAnsi`=Times New Roman、`w:eastAsia`=宋体。这是正式文档规范，不设eastAsia中文会掉成等线体
- 版式：居中大标题「招投标信息汇总」→灰字查询原话→灰字元信息块（生成时间/检索条件/来源站点/新增条数）→分隔线→逐条（加粗标题、灰字来源+日期、首行缩进正文、蓝色原文链接）
- 文件名：`{原话清洗}_{yyyyMMddHHmm}.docx`，非法字符替换为下划线，限40字

### 2.5 定时（scheduler.py）

APScheduler BackgroundScheduler，Asia/Shanghai。标准cron周日=0映射到day_of_week名称，`?`视作`*`。任务id=`bid-`+md5(query|cron)[:10]，replace_existing=True防重复注册；max_instances=1防重入；misfire_grace_time=300秒。

**明确边界：不持久化JobStore**。进程重启任务丢失——竞赛演示可接受，生产化再换SQLAlchemyJobStore，接口不变。

### 2.6 推送（push/emailer.py）

SMTP协议，`smtplib`。构造与发送分离：`_build_message()`只拼MIME零网络副作用（便于自检），`_send()`才落地传输——这是能用假凭据验隔离性的前提。

- **服务器推断**：按发件邮箱域名查`_SMTP_PRESETS`（qq/foxmail/163/126/sina/gmail/outlook），465口走`SMTP_SSL`，其余走`starttls()`。126/163系直接用465，免STARTTLS协商坑
- **凭据**：优先级 `环境变量 > config/secrets.yaml > config/config.yaml`。默认只从`secrets.yaml`取（`load_config`深合并覆盖），`config.yaml`里留空壳。环境变量通道（`BIDAGENT_SMTP_ENABLED/USERNAME/PASSWORD/TO`）用于容器、CI 与临时覆盖，只收集真正设置过的键；显式传`path`加载配置时不读环境，保证测试可复现。启动日志打印「凭据来源」避免改了文件却没生效
- **结构**：`multipart/mixed` → `multipart/alternative`（`text/plain`＋`text/html`）＋docx附件。双正文是因为手机端和桌面端渲染偏好不同，纯文本兜底保证任何客户端都可读
- **摘要上限**：`max_items_in_digest=8`，条目速览带原文直链——邮件是"通知＋可点"，全文仍在附件里
- **失败语义**：`SMTPAuthenticationError`明确提示"填的是授权码不是登录密码"；推送失败只进`warnings`，不影响文档生成与主流程
- **状态口**：`status()`返回`{enabled, ready, username, recipients}`，`/api/health`透出，前端据此亮"邮件就绪/缺凭据/未启用"药丸

## 3. 关键设计决策与理由

| 决策 | 理由 | 代价与对策 |
|---|---|---|
| 规则解析打底，LLM外挂 | 模型失败不能阻断链路；规则覆盖赛题示例已够演示 | 同义表达覆盖弱→llm_parser已留位，回退机制现成 |
| 登录态站点明确报错 | needs_login=true时HTTP抓取抛LoginRequiredError进warnings，绝不静默漏数据 | 真实能力由Playwright侧车补（v2） |
| 单体切包而非双服务 | 竞赛场景跨进程跳转纯属开销；包边界已足够隔离 | 未来真要拆分，Protocol接口原样可用 |
| SQLite而非Redis | 指纹量级（万级）单文件零运维够用；拷走即备份 | 百万级指纹再换Redis，只重写一个类 |
| mock客户端刻意造脏数据 | 广告噪声+重复条目+超长正文，用来验证清洗与去重真的生效 | — |
| dataclass而非ORM/pydantic全栈 | 中间数据结构在任何一步都能print检查，vibe coding审查成本低 | config层用pydantic强校验，配错启动即报 |
| 凭据默认走secrets覆盖层，环境变量作可选高优先通道 | 双击启动拿不到临时shell变量，文件可持久、可gitignore、可ACL收紧；容器/CI没有文件可放时用环境变量 | 两套来源必须有明确优先级（env > secrets > config），启动日志打印来源，避免"改了文件却没生效" |
| 显式传路径加载配置时不读环境变量 | 测试与多环境要求可复现，环境噪声会污染断言 | 该分支禁用env覆盖，由调用方自行保证 |
| 推送失败只进warnings | 通知渠道不该成为主链路的单点 | 需要强中断时读`pushed_to`是否为空自行判断 |

## 4. 错误处理约定

- 业务错→`BizException(status_code=4xx)`→统一响应体`{success, message, data}`
- 单站点抓取失败→计入`warnings`，不拖垮整轮
- 未预期异常→500＋`{type}`名，完整堆栈只进日志不进响应
- 路径穿越防护：`/api/files/{name}`只接受纯文件名，`resolve()`后校验父目录
