### 驳回（写明理由，防止重提）

- **指纹按查询作用域**——归类错误：是产品语义不是 bug。「见过就不推第二遍」是单用户工具的免打扰设计；运行历史可验证它在工作（`fresh` 17→0→0）。改成按关键词隔离后同一公告会在每个查询里各推一次。
- **slim / full 双 Docker tag**——抓错了成本：真实成本是 618MB 离线包重传，属发布流程；拆镜像没有消费者，exe（61.7MB）已经是轻量形态。
- **后台 job 队列 + `/api/jobs/{id}` 轮询**——过度设计，且「可能超 120 秒」是推断非实测（历史实际 11～81 秒）。锁 + 409 + 300s 覆盖全部场景。
- **前端拆 11 个组件（方案 B）**——套模板：517 行未到要拆的量级，「哪儿都不贴」的根因在 CSS token 与层级，不在文件长度。

### 缓办

- P2-3 教学段落迁 `docs/notes/`：README 一屏化随工程化轮做，搬家缓。教学记录按「保留不删」原则留在原处。
- 启动时检测另一实例并拒启：`data_dir` 已能让人自查；真实风险场景（exe 与容器共用 `data/`）README 有警告。

### 一条改了实施位置的建议

**并发锁挂 `PipelineService.run`，不是路由层。** 定时入口（`app/main.py` 的 `_run_scheduled`）与接口入口（`app/api/routes.py` 的 `/pipeline/run`）都直接调用它，只在路由层加锁挡不住「定时任务 + 手动点一次」并发——而这正是 P0-3 的并发场景。实施要点：

1. `run()` 入口对进程内锁做非阻塞 `acquire`，拿不到就抛 `BizException(status_code=409)`，由全局异常处理器转成接口响应。
2. `_run_scheduled` 单独捕获这个「忙」信号，记一条「上一轮仍在执行，本轮跳过」。它现在是 `except Exception: log.exception`，会把「忙」当成故障打出堆栈。

## 三、执行纪律

- 每轮结束照例回写开发日志（五段式）；版号、Release、资产三处同步的既有流程不变。
- 驳回项若条件变化（如出现第二个真实使用者），须重新过本文档再立项，不直接动手。
- 评审建议先分「产品语义 / 缺陷 / 工程化」三类再排序；把产品语义写进 bug 清单，改动会破坏原有设计。
- 每条建议都要能回答「谁在为它付费、它替代了什么」，否则就是给不存在的需求提方案。
- 并发类修复先确认所有调用入口——锁的位置比锁的存在更关键。
- 验收任何分发物时，health 断言里必须带 `version`，不符立即停。2026-11-28 实测踩过：onefile 的引导进程停了、服务子进程还在，占着 8000，下一次验证打到的是上一版。
