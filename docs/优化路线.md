### 驳回（写明理由，防止以后重提）

- **P0-3 的「指纹按查询作用域」**——这是产品语义变更，不是 bug。当前单用户工具，全局语义＝「见过的公告不再推第二遍」，说得通；改成按关键词隔离后，同一公告会在两个查询里各推一次，用户大概率更烦。先在 README 写明全局语义，等真出现第二使用场景（多人各订阅各的）再改结构。
- **P1-3 的 slim/full 双 tag**——exe 就是 slim 形态（61.7MB 无浏览器），再加一个无浏览器 docker tag 是给不存在的需求买单；590MB 离线包是无网演示专用，不是常态分发物。
- **P1-1 的后台 job 队列 + /api/jobs/{id} 轮询**——单机单用户，锁 + 409 + 300s 已覆盖全部实际场景，队列是过度设计。
- **P2-2 的组件拆分**——517 行单页没到要拆的复杂度，拆了反增认知成本。

### 缓办（有价值但不在前三轮）

- P2-3 文档大迁移（教学段落挪 `docs/notes/`）：README 一屏化本轮做，搬家缓。教学记录对项目本身有价值（保留不删原则），外部读者靠 README 分流即可。
- 启动时检测另一实例并拒启：真实风险是「exe 与容器共用 data/ 双跑定时任务」，README 已警告；health 暴露 `data_dir` 后用户可自查。
