# AI-Bid-Agent 操作指南

面向日常使用与交接。当前`crawler.mock=false`：合肥公共资源交易中心（工程建设 002001／政府采购 002002）走真实接口，其余站点未启用（原因见`config.yaml`注释）。

## 1. 启动与停止

**方式一（推荐）：双击项目根目录的`启动.bat`**——自动起服务并打开浏览器，`.bat`不受执行策略限制，`Ctrl+C`或关窗即停止。

**方式二：PowerShell 标准姿势**

```powershell
cd "D:\Misc\竞赛\33.2026年飞书AI未来人才大赛（已结束）\AI-Bid-Agent"
.\run.ps1
```

`.ps1`不允许双击运行（双击＝记事本打开代码，这是Windows安全设计）。若报「禁止运行脚本」，执行一次并按Y，此后永久生效：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**方式三：地址栏速启**——在文件夹的资源管理器地址栏输入`powershell`回车，再执行`.\run.ps1`。

注意：8000端口同时只能有一个服务。本助手后台起的实例未停时再手动启动会报端口占用，先喊助手停掉或用`Get-NetTCPConnection -LocalPort 8000`查PID。

启动成功的标志：日志出现`启动完成 | mock=True | 站点=2 | 指纹=0 | 解析器=rule`，且`http://127.0.0.1:8000/docs`能打开自带的Swagger界面。

前提：`frontend/dist`已构建（`cd frontend; npm install; npm run build`）。未构建时页面打不开但API照常——先构建再重启。

## 2. 浏览器演示（推荐，约1分钟）

浏览器打开`http://127.0.0.1:8000/`，按顺序：

1. **看头部药丸**：解析器（rule／llm）、启用站点数、指纹数、邮件状态（就绪／缺凭据／未启用）——证明服务活着
2. **点示例短语 →「仅解析意图」**：关键词/区域/时间/cron四字段——证明听得懂人话
3. **点「执行全链路」**：统计卡抓取/新增/去重、条目表（标题可点、摘要可折叠）、"邮件已推送至"提示——证明干得出来；点文档表「下载」打开Word看版式
4. **原样再点一次「执行全链路」**：新增0、提示「本轮无新增条目」——证明增量推送是真的
5. **点「测试邮件」**：收件箱应立刻收到一封测试信——证明通知渠道通着
6. **定时任务表**：看下次执行时间，点「删除」验证任务生命周期

## 3. 命令行演示（curl，与浏览器操作等价）

按顺序执行，每步都有明确的“看什么”：

**第1步：证明活着**

```powershell
curl http://127.0.0.1:8000/api/health
```

看点：`mock=false`（当前真实模式）、两个合肥站点、`fingerprints`数、`push.ready=true`且`recipients>=1`（邮件已就绪）。

**第2步：证明听得懂人话**

```powershell
curl -X POST http://127.0.0.1:8000/api/intent/parse -H "Content-Type: application/json" -d "{\"query\": \"最近3个月的合肥充电桩招标信息都有哪些，请汇总后每天9:00发送给我\"}"
```

看点：`keyword=充电桩`、`region=合肥`、`time_range_text=最近3个月`、`cron=0 9 * * *`——与赛题示例同构。

**第3步：证明干得出来**

```powershell
curl -X POST http://127.0.0.1:8000/api/pipeline/run -H "Content-Type: application/json" -d "{\"query\": \"最近2个月的合肥充电桩招标信息都有哪些，请汇总后每天9:00发送给我\"}"
```

看点：`fetched`／`fresh`／`deduplicated`（真实模式下数值随公告量浮动，首轮通常抓20~30条、去重0~几条）；`doc_path`指向生成的Word；`pushed_to`非空说明邮件已带附件发出；`scheduled_job`返回任务id。打开`output/`里的docx看版式（标题/检索条件/逐条来源日期链接）。

**第4步：证明增量推送是真的**

原样再跑一次第3步。

看点：`fresh=0`、`doc_path`为空、`warnings`提示“本轮无新增条目，未生成文档（增量推送语义）”。

**第5步：证明定时任务挂上了**

```powershell
curl http://127.0.0.1:8000/api/tasks
```

看点：`next_run`是明天9:00。删除用：

```powershell
curl -X DELETE http://127.0.0.1:8000/api/tasks/bid-xxxxxxxxxx
```

**彩蛋：演示“首次全量vs二次增量”对比**

```powershell
curl -X POST http://127.0.0.1:8000/api/fingerprints/clear   # 清库
curl -X POST http://127.0.0.1:8000/api/pipeline/run ...      # 又变回全量 fresh=8
```

## 4. 真实站点：现状与加站方法

**现状**：`crawler.mock: false`，已接通合肥公共资源交易中心两个类目（工程建设`002001`、政府采购`002002`）。中国政府采购网被WAF拦死、全国公共资源交易平台旧域名已停止解析且新门户是JS渲染——两者留待Playwright侧车，站点配置里如实注明后置`enabled: false`。

**加一个新站点**，按站点返回形态选一种模式：

- **HTML模式**（老字段）：`list_url`＋`item_selector/title_selector/date_selector/link_selector`，`data_format`留空
- **JSON接口模式**：`data_format: json`，配全套`json_*`字段——`json_items_path`（点号路径，如`custom.infoList`；值若还是JSON字符串会自动二次解析）、`json_title_field`/`json_date_field`/`json_url_field`、`json_url_template`（如`/jyxx/{大类}/{categorynum}/{infodate2.compact}/{infoid}.html`，支持`{字段}`与`{字段.compact}`压缩日期、`{start_date}{end_date}`日期占位）、`json_content_fields`（正文取哪几个字段拼接）、`request_headers`（有些站要Referer）

加完先小范围试：`POST /api/intent/parse`看清意图，再`POST /api/pipeline/run`核对返回条目标题、日期、链接与真实站点一致，最后确认链接能打开。

真实站点失败时看`warnings`——单站失败不拖垮其他站点，也不会静默漏数据。

## 5. 启用邮件推送（126/163 授权码）

**第1步：拿到授权码**（不是登录密码）。网页登录发件邮箱 → 设置 → 账号（POP3/IMAP/SMTP）→ 开启「SMTP服务」→ 手机短信验证 → 生成授权码，抄下来。126/163 系同一份授权码对SMTP/POP3通用，所以开哪个都行，关键是SMTP服务必须是开启状态。

**第2步：写本地密钥**。复制`config/secrets.yaml.example`为`config/secrets.yaml`，填四项：

```yaml
push:
  email:
    enabled: true
    username: "你的发件邮箱@126.com"
    password: "授权码，16位那串"
    to_addrs:
      - "收件邮箱@163.com"
```

`config/secrets.yaml`已在`.gitignore`里（第20行），**永远不会进仓库**；`config.yaml`里那份`push.email`只作字段占位，真实值一律走覆盖层，所以公开仓库里看不到任何邮箱和授权码。

**第3步：重启服务**，看头部药丸变成「邮件就绪」，或`curl http://127.0.0.1:8000/api/health`看`push.ready=true`。

**第4步：点「测试邮件」**（等价`POST /api/push/test`），收件箱应收到一封测试信；也可以直接命令行验证：

```powershell
curl -X POST http://127.0.0.1:8000/api/push/test -H "Content-Type: application/json" -d "{}"
```

**触发时机**：真实跑一轮`/api/pipeline/run`且产生文档时自动发——Word作附件，正文是纯文本＋HTML双版摘要（条目速览带原文链接，最多8条），响应里`pushed_to`会回填收件人。

服务器不用手填：按发件邮箱域名自动推断（126→`smtp.126.com:465`、163→`smtp.163.com:465`、QQ→`smtp.qq.com:465`，其余走STARTTLS）。

**凭据安全（每次提交前跑一遍）**

```powershell
pwsh -File scripts\audit_secrets.ps1
```

脚本不含任何密钥字面量（运行时从`secrets.yaml`读出待查字符串再比对），所以它本身可以安全入库。七项检查：gitignore是否覆盖、全部提交里有无授权码、全部提交里有无凭证字段、已跟踪文件里有无授权码/真实邮箱、本机磁盘是否有`secrets.yaml`之外的副本、命令历史有无残留、远端可见性提示。全绿退出码0，有命中退出码1。

`secrets.yaml`的文件权限已收紧为**仅当前用户＋SYSTEM＋Administrators**可读写（去掉了`BUILTIN\Users`）。换机器或换账户后需重设一次：

```powershell
icacls config\secrets.yaml /inheritance:r /grant:r "$([System.Security.Principal.WindowsIdentity]::GetCurrent().Name):(F)" "SYSTEM:(F)" "BUILTIN\Administrators:(F)"
```

## 6. 启用LLM解析（可选）

```powershell
$env:BIDAGENT_LLM_API_KEY = "sk-..."
$env:BIDAGENT_LLM_BASE_URL = "https://api.deepseek.com/v1"   # 默认
$env:BIDAGENT_LLM_MODEL = "deepseek-chat"                     # 默认
# config.yaml: intent.parser 改为 llm
```

模型不可用或超时会**自动回退规则解析**，`intent.parser`字段会标成`llm-fallback(...)`，链路不断。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报`配置文件不存在` | 不在项目根目录运行 | `cd`到AI-Bid-Agent目录再`.\run.ps1` |
| 中文乱码 | 控制台编码 | run.ps1已设`PYTHONIOENCODING=utf-8`；手动跑时先设同样变量 |
| 端口8000被占 | 其他进程 | `Get-NetTCPConnection -LocalPort 8000`查PID，或改config.yaml的port |
| 重启后定时任务没了 | APScheduler不持久化（详设2.5已声明） | 重新跑一次带频率的原话即可 |
| 报`没能识别出检索关键词` | 原话全是虚词（如“帮我看一下”） | 按“时间+区域+主题+招标信息”重说 |
| 想彻底重来 | 指纹库污染 | 页面点「清空指纹」，或`POST /api/fingerprints/clear`，或删`data/bidagent.db` |
| 页面打不开（404） | `frontend/dist`未构建 | `cd frontend; npm install; npm run build`后重启`run.ps1` |
| 改了前端没生效 | 浏览器缓存或未重新构建 | 重新`npm run build`＋Ctrl+F5强刷 |
| 药丸显示「缺凭据」 | 没写`config/secrets.yaml`或字段不全 | 照第5节填`username/password/to_addrs`，重启 |
| 药丸显示「未启用」 | `push.email.enabled`为false | secrets里设`enabled: true`，重启 |
| 报`535 Authentication failed` | 填了登录密码而不是授权码，或SMTP服务没开 | 回网页邮箱重新生成授权码，确认SMTP已开启 |
| 收不到信但接口报成功 | 进垃圾箱或被反垃圾拦 | 查垃圾邮件箱，把发件地址加白名单 |
