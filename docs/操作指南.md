# AI-Bid-Agent 操作指南

面向日常使用与交接。当前`crawler.mock=false`：合肥公共资源交易中心（工程建设 002001／政府采购 002002）走真实接口，其余站点未启用（原因见`config.yaml`注释）。

## 1. 启动与停止

**方式一（推荐，当前默认形态）：Docker 容器**

```powershell
cd "<项目根>"
docker compose -f deploy/docker-compose.yml up -d --build   # 起两个容器
docker compose -f deploy/docker-compose.yml ps              # 看状态
docker compose -f deploy/docker-compose.yml down            # 停并删容器（不动 data/、output/）
```

浏览器打开 **`http://127.0.0.1/`**（80 端口，不是 8000）。组成：`app`（python:3.12-slim，uvicorn 8000，仅容器内网，不映射宿主端口）＋`nginx`（alpine，宿主 80，托管`frontend/dist`并把`/api/`反代到`app:8000`）。`data/`、`output/`挂宿主机目录，删容器数据不丢；`config/secrets.yaml`只在运行时以只读卷挂入，**镜像里没有凭据**（根目录`.dockerignore`已排除）。

常态无需手动启动：Docker Desktop 已设登录自启（Windows 启动项`Docker Desktop`已启用），容器策略`restart: unless-stopped`。开机登录后等引擎就绪十几秒，`http://127.0.0.1/` 直接可用；重装 Docker Desktop 后这两项设置需重做。

三条硬约束：

1. **不要与方式五（宿主常驻）同时跑**。两种形态共用`data/bidagent.db`，同一批定时任务会被两套调度器各跑一次，导致重复推送与重复文档。切换前先停另一侧。
2. 国内网络直连 Docker Hub 常被重置，拉基础镜像可走镜像源再改回官方名：`docker pull docker.m.daocloud.io/library/python:3.12-slim` → `docker tag ... python:3.12-slim`（nginx 同法）。
3. 80 端口若被别的程序占用，改`docker-compose.yml`里 nginx 的`ports: "127.0.0.1:8080:80"`，再访问`http://127.0.0.1:8080/`。

**访问范围与门禁（默认只允许本机）**

`docker-compose.yml` 把 nginx 的端口绑死为 `127.0.0.1:80:80`，镜像端口只映射到回环地址——同一网络里的其他人（含校园网、宿舍局域网）打不开，实测本机各网卡地址 `:80` 均连接被拒。这是当前唯一有效的门禁。

**要放宽到局域网/给评委看，必须两件事一起做，缺一不可**：

1. 端口改回 `"80:80"`（只改这个等于把能发邮件、能清指纹库的接口敞开）
2. 启用 `deploy/nginx.conf` 顶部的 Basic Auth 段——生成口令文件、挂载、取消两行注释，步骤已写在文件注释里；`deploy/htpasswd` 已在`.gitignore`，不会进仓库

这套系统**不做用户系统**：单人单租户，没有"谁的数据归谁"的问题，账号体系带来的注册/重置/会话/权限全是新攻击面与维护负担，收益为零。真要对外演示，比登录更管用的是"演示模式"（在配置层禁掉 `push`、`schedule`、`fingerprints/clear` 三个写操作），评委看得到完整界面与数据，但点不出副作用。

**为什么这条规矩这么硬、为什么"以为关着"比"确实开着"更危险、三个接口被点到分别会发生什么、网络层与应用层校验的分工**——完整推理见 `docs/安全边界与门禁.md`。那份文档是写给"熟悉后端参数校验、不熟网络边界"的读者，含术语小抄（回环、端口映射、反向代理、401/403）。

**方式二（备选，无 Docker 时）：双击项目根目录的`启动.bat`**——自动起服务并打开浏览器，`.bat`不受执行策略限制，`Ctrl+C`或关窗即停止。

**方式三：PowerShell 标准姿势**

```powershell
cd "D:\Misc\竞赛\33.2026年飞书AI未来人才大赛（已结束）\AI-Bid-Agent"
.\run.ps1
```

`.ps1`不允许双击运行（双击＝记事本打开代码，这是Windows安全设计）。若报「禁止运行脚本」，执行一次并按Y，此后永久生效：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**方式四：地址栏速启**——在文件夹的资源管理器地址栏输入`powershell`回车，再执行`.\run.ps1`。


**方式五（备选，当前未启用）：服务化常驻**——注册一次，开机自启、崩溃自愈，不再需要任何双击：

```powershell
pwsh -ExecutionPolicy Bypass -File service\register.ps1     # 注册（只需一次）
pwsh -ExecutionPolicy Bypass -File service\unregister.ps1   # 卸载
```

注册后系统里出现两个计划任务：`AI-Bid-Agent`（登录自启，隐藏窗口）＋`AI-Bid-Agent-Watchdog`（每 5 分钟检查端口，服务不在就拉起）。三个保证：①端口已被占用时自动退出，绝无双开；②进程被误杀最多 5 分钟自愈；③定时任务重启不丢（见下）。浏览器随时开`http://127.0.0.1:8000/`即可，**服务常驻时不要再双击`启动.bat`**（会报端口占用）。当前已切换为 Docker 形态，两个计划任务已由`unregister.ps1`卸掉；要退回宿主常驻需先`docker compose down`再`register.ps1`。

注意：8000端口同时只能有一个服务。本助手后台起的实例未停时再手动启动会报端口占用，先喊助手停掉或用`Get-NetTCPConnection -LocalPort 8000`查PID。

启动成功的标志：日志出现`启动完成 | mock=True | 站点=2 | 指纹=0 | 解析器=rule`，且`http://127.0.0.1:8000/docs`能打开自带的Swagger界面。

前提：`frontend/dist`已构建（`cd frontend; npm install; npm run build`）。未构建时页面打不开但API照常——先构建再重启。

**方式六（交付给无环境机器）：单文件 exe**

```powershell
pwsh -ExecutionPolicy Bypass -File scripts\build_exe.ps1     # 一键构建（约 1 分钟）
# 产物 dist\AI-Bid-Agent.exe（约 21MB），双击即用——无需 Python、无需 Docker、无需 npm
```

把 exe 拷到任何 Windows 机器的一个文件夹里双击即可：浏览器自动打开 `http://127.0.0.1:8000/`，首次运行会在 exe 旁生成 `config\`（可编辑）、`data\`、`output\`——拷走整个文件夹即完成迁移。前端页面与配置模板都内嵌在 exe 里；`config\secrets.yaml.example` 也放在旁边，填好改名为 `secrets.yaml` 即启用邮件。仅绑 127.0.0.1，不对外网开放。注意：与 Docker 形态共用 `data/bidagent.db` 时别同时开定时任务；exe 适合演示与分发，常驻服务仍推荐 Docker 形态。

## 2. 浏览器演示（推荐，约1分钟）

浏览器打开`http://127.0.0.1/`（Docker 形态走 nginx 80 端口；宿主常驻形态则用 8000），按顺序：

1. **看头部药丸**：解析器（rule／llm）、启用站点数、指纹数、邮件状态（就绪／缺凭据／未启用）——证明服务活着
2. **点示例短语 →「仅解析意图」**：关键词/区域/时间/cron四字段——证明听得懂人话
3. **点「执行全链路」**：统计卡抓取/新增/去重、条目表（标题可点、摘要可折叠）、"邮件已推送至"提示——证明干得出来；点文档表「下载」打开Word看版式
4. **原样再点一次「执行全链路」**：新增0、提示「本轮无新增条目」——证明增量推送是真的
5. **点「测试邮件」**：收件箱应立刻收到一封测试信——证明通知渠道通着
6. **定时任务表**：看下次执行时间，点「删除」验证任务生命周期

## 4. 真实站点：现状与加站方法

**现状**：`crawler.mock: false`，已接通合肥公共资源交易中心两个类目（工程建设`002001`、政府采购`002002`）。中国政府采购网被WAF拦死、全国公共资源交易平台旧域名已停止解析且新门户是JS渲染——两者留待Playwright侧车，站点配置里如实注明后置`enabled: false`。

**加一个新站点**，按站点返回形态选一种模式：

- **HTML模式**（老字段）：`list_url`＋`item_selector/title_selector/date_selector/link_selector`，`data_format`留空
- **JSON接口模式**：`data_format: json`，配全套`json_*`字段——`json_items_path`（点号路径，如`custom.infoList`；值若还是JSON字符串会自动二次解析）、`json_title_field`/`json_date_field`/`json_url_field`、`json_url_template`（如`/jyxx/{大类}/{categorynum}/{infodate2.compact}/{infoid}.html`，支持`{字段}`与`{字段.compact}`压缩日期、`{start_date}{end_date}`日期占位）、`json_content_fields`（正文取哪几个字段拼接）、`request_headers`（有些站要Referer）

加完先小范围试：`POST /api/intent/parse`看清意图，再`POST /api/pipeline/run`核对返回条目标题、日期、链接与真实站点一致，最后确认链接能打开。

真实站点失败时看`warnings`——单站失败不拖垮其他站点，也不会静默漏数据。

## 5. 启用邮件推送（126/163 授权码）

**第1步：拿到授权码**（不是登录密码）。网页登录发件邮箱 → 设置 → 账号（POP3/IMAP/SMTP）→ 开启「SMTP服务」→ 手机短信验证 → 生成授权码，抄下来。126/163 系同一份授权码对SMTP/POP3通用，所以开哪个都行，关键是SMTP服务必须是开启状态。

**第2步：写本地密钥**。复制`config/secrets.yaml.example`为`config/secrets.yaml`，填四项：

```yaml
push:
  email:
    enabled: true
    username: "你的发件邮箱@126.com"
    password: "授权码，16位那串"
    to_addrs:
      - "收件邮箱@163.com"
```

`config/secrets.yaml`已在`.gitignore`里（第20行），**永远不会进仓库**；`config.yaml`里那份`push.email`只作字段占位，真实值一律走覆盖层，所以公开仓库里看不到任何邮箱和授权码。

**第3步：重启服务**，看头部药丸变成「邮件就绪」，或`curl http://127.0.0.1:8000/api/health`看`push.ready=true`。

**另一种方式：环境变量（可选，适合容器/CI/临时覆盖）**

优先级是 **环境变量 > `config/secrets.yaml` > `config/config.yaml`**，启动日志会打印「凭据来源」告诉你当前用的是哪一条。四个变量（不设就不参与覆盖，不会把文件里的值冲空）：

```powershell
$env:BIDAGENT_SMTP_ENABLED  = "true"
$env:BIDAGENT_SMTP_USERNAME = "发件邮箱"
$env:BIDAGENT_SMTP_PASSWORD = "授权码"
$env:BIDAGENT_SMTP_TO       = "a@163.com,b@qq.com"   # 逗号/分号/空格分隔
```

注意三个坑：① 这样设的变量只活在当前窗口，**双击`启动.bat`启动的服务读不到**，会显示「缺凭据」；② 要持久化得用 `setx`，值会落在注册表`HKCU\Environment`，**任何以你身份运行的进程都能读到**，安全性并不比ACL收紧过的文件更高，而且会被子进程继承；③ 改完变量必须重启服务（配置在启动时读取一次）。

它的真正价值是**与代码目录物理分离**——把整个项目文件夹打包发给别人时不会带走凭据，以及容器/CI 里没有文件系统可放。

**第4步：点「测试邮件」**（等价`POST /api/push/test`），收件箱应收到一封测试信；也可以直接命令行验证：

```powershell
curl -X POST http://127.0.0.1:8000/api/push/test -H "Content-Type: application/json" -d "{}"
```

**触发时机**：真实跑一轮`/api/pipeline/run`且产生文档时自动发——Word作附件，正文是纯文本＋HTML双版摘要（条目速览带原文链接，最多8条），响应里`pushed_to`会回填收件人。

服务器不用手填：按发件邮箱域名自动推断（126→`smtp.126.com:465`、163→`smtp.163.com:465`、QQ→`smtp.qq.com:465`，其余走STARTTLS）。

**凭据安全（每次提交前跑一遍）**

```powershell
pwsh -File scripts\audit_secrets.ps1
```

脚本不含任何密钥字面量（运行时从`secrets.yaml`读出待查字符串再比对），所以它本身可以安全入库。七项检查：gitignore是否覆盖、全部提交里有无授权码、全部提交里有无凭证字段、已跟踪文件里有无授权码/真实邮箱、本机磁盘是否有`secrets.yaml`之外的副本、命令历史有无残留、远端可见性提示。全绿退出码0，有命中退出码1。

**误删保险：`config/secrets.yaml.bak`（自动维护）**

服务每次启动会做两件事：

1. **漂移检查**：拿当前`secrets.yaml`与`.bak`比对八个关键字段（邮件三项/飞书钉钉各两项/LLM key）。备份里有值而当前为空的，启动日志直接告警点名——历史上发生过「编辑时新建`push:`段把 email 段整个顶掉、授权码丢失」的事故，这个检查就是为它而生。
2. **刷新快照**：确认无漂移才把当前文件复制为`.bak`；文件解析失败或字段疑似误删时**不覆盖**备份，最后一份完好的永远保留。

误删后恢复：把`config/secrets.yaml.bak`复制回`config/secrets.yaml`，重启。注意`.bak`同样在`.gitignore`与`.dockerignore`里，绝不入 git、不进镜像；权限与主文件一致收紧（仅当前用户＋SYSTEM＋Administrators）。换机器或换账户后需对两个文件重设一次：

```powershell
icacls config\secrets.yaml /inheritance:r /grant:r "$([System.Security.Principal.WindowsIdentity]::GetCurrent().Name):(F)" "SYSTEM:(F)" "BUILTIN\Administrators:(F)"
icacls config\secrets.yaml.bak /inheritance:r /grant:r "$([System.Security.Principal.WindowsIdentity]::GetCurrent().Name):(F)" "SYSTEM:(F)" "BUILTIN\Administrators:(F)"
```

## 6. 群机器人推送（飞书 / 钉钉，可选）

邮件之外的第二个通道，**两个平台都接了**，各自独立开关。和邮件并行：同时开两个，同一条消息会进两个群；任一渠道失败只进 `warnings`，不拖累主流程和另一渠道。

**先分清一件事**：飞书是**字节跳动**的，钉钉是**阿里**的，不是一家，账号与机器人体系完全独立，钉钉的配置经验**不能直接平移**。但概念层约七成同构——都是「群里加个自定义机器人 → 拿到一条 webhook 地址 → POST 一个 JSON」。真正会咬人的只有三处：地址域名、JSON 字段名、加签算法。

| 维度 | 飞书 | 钉钉 |
|---|---|---|
| webhook 地址 | `https://open.feishu.cn/open-apis/bot/v2/hook/<token>` | `https://oapi.dingtalk.com/robot/send?access_token=<token>` |
| 文本消息体 | `{"msg_type":"text","content":{"text":"…"}}` | `{"msgtype":"text","text":{"content":"…"}}` |
| 富文本/卡片 | `{"msg_type":"post","content":{"post":{"zh_cn":{"title","content":[[…]]}}}}`（本项目用它，正文分标题＋段落） | `{"msgtype":"markdown","markdown":{"title","text"}}`（本项目用它，正文是 markdown） |
| 加签算法 | `sign = base64(HMAC-SHA256(key="{秒级ts}\n{secret}", msg=""))`，`ts`/`sign` 放**body** | `sign = urlencode(base64(HMAC-SHA256(key=secret, msg="{毫秒级ts}\n{secret}"))`，`ts`/`sign` 拼在**URL query** |
| 成功响应 | `{"code":0,"msg":"success"}` | `{"errcode":0,"errmsg":"ok"}` |
| 签名错误码 | `19021`（sign match fail） | 常见 `310000`（sign not match） |

**最关键的一条**：两家加签的 key 与 msg **位置正好互换**。把钉钉那套照抄到飞书必然 19021。所以本项目给两条算法各写了一条硬编码向量的回归测试（`tests/test_webhook.py`），谁“顺手优化”都会立刻红。

**开四步**：

1. 在群里建机器人：飞书是「群设置 → 群机器人 → 添加机器人 → 自定义机器人」；钉钉是「群设置 → 机器人 → 添加机器人 → 自定义」。
2. 安全设置**建议勾「签名校验/加签」**（比关键词校验严，不依赖标题里恰好含某个词）；拿到密钥。
3. 把地址与密钥写进 `config/secrets.yaml`（照 `secrets.yaml.example` 的 `push.feishu` / `push.dingtalk` 段）。`config.yaml` 里那两段只留空壳，公开仓库看不到真实地址——webhook 地址本身就是凭据，泄露等于任何人都能往你群里发消息。
4. 重启服务，头部应出现「飞书群就绪 / 钉钉群就绪」药丸；点「推送自测」（等价 `POST /api/push/test`，一次测所有已启用渠道）。

**触发时机与邮件一致**：真实跑一轮且产生文档时自动推，条目速览取前 5 条（`max_items_in_digest` 可调），超出部分提示「另有 N 条见 Word」。响应里 `pushed_to` 回填渠道名：邮件填收件人，群机器人填 `飞书群` / `钉钉群`。

**只想要一个渠道**：把另一段 `enabled` 改 false 即可，或干脆不填地址（地址为空一律视为未配置，不会尝试发送、不会报错）。

## 7. 模型摘要（summary，默认开）

抓完并去重后，让模型读一遍新增条目，产出三样东西：**一句总体判断**、**最多 3 条"最值得盯"**（每条带"为什么值得看"和"风险提示"）。它落三个地方——Word 首页的「重点速览」、邮件正文顶部、群消息开头。

**凭什么敢让它写**：prompt 里只允许模型输出条目**编号**，标题、链接、来源、日期全部由代码按编号回填。编号越界或不是整数就丢弃，绝不"按标题硬配"。所以它可能判断得平庸，但**编不出一条不存在的公告**。

**开与关**（`config.yaml`）：

```yaml
summary:
  enabled: true        # 关掉就完全不调模型，其余链路不受影响
  max_picks: 3         # 最多挑几条
  max_items_in_prompt: 20   # 送进模型的条数上限
  timeout_seconds: 60  # 推理模型首句思考时间长，别给 10 秒
```

**用哪个模型**：默认沿用 `intent.llm` 的 key 与模型（当前 glm-5.3-flash）。想"解析用便宜的、摘要用强的"，只改 `summary` 段三个字段：

```yaml
summary:
  model: "glm-5.3-flash"     # 留空则沿用 intent.llm.model
  base_url: ""               # 留空则沿用
  api_key: ""                # 留空则沿用
```

**触发条件**：`write_doc=true` **且本轮有新增**。无新增不产文档、也就没有摘要（不白烧 token）；`write_doc=false` 的快速解析也不调模型。

**失败了会怎样**：未配 key、401/429、超时、模型返回不是 JSON、挑不出有效条目——一律降级为"本轮无摘要"，原因写进响应的 `warnings`，**文档与推送照常**。页面上摘要卡整块消失，不会出现空壳。

**健康状态**：`curl http://127.0.0.1:8000/api/health` 看 `summary.enabled` 与 `summary.model`；启动日志有一行「摘要=就绪/未启用」。

**成本感受**：一次摘要约 8 条×180 字正文，输入几千 token 级，输出几百 token。智谱 500 万体验包按日常演示频率基本用不完；真到 12 月 27 日到期，改 `model` 一行回免费档即可。

## 8. 启用LLM解析（hybrid，推荐）

三种模式（`config.yaml` 的 `intent.parser`）：

| 模式 | 行为 | 适用 |
|---|---|---|
| `rule` | 纯正则，零成本 | 没有 key 时的默认 |
| `llm` | 全部走模型，失败自动回退 rule | 调试模型效果 |
| `hybrid` | **规则先行**，仅当关键词缺失/垃圾、或疑似有频率但没解出 cron 时才调模型补空缺 | **推荐**——标准句零成本，口语句才花钱 |

**开三步**：

1. 把 key 写进 `config/secrets.yaml`（照着 `secrets.yaml.example` 的 `intent.llm` 段填），或容器场景用环境变量：

```yaml
intent:
  llm:
    api_key: "sk-..."
    # base_url / model：DeepSeek 用默认；豆包填 ark 的 /api/v3 + ep- 开头接入点 ID；千问填 compatible-mode/v1 + qwen-plus
```

2. `config.yaml` 确认 `parser: hybrid`。
3. 重建容器：`docker compose -f deploy/docker-compose.yml up -d --build`。

**怎么看生效**：`/api/health` 的 `parser` 字段——`hybrid`（模型可用）／`hybrid(no-llm)`（配置了 hybrid 但没 key，等效 rule）；单次解析结果的 `parser` 字段标注细粒度状态：`rule`（规则独立完成，没花钱）、`hybrid(frequency-suspect)`／`hybrid(keyword-missing)`（升级过模型）、`hybrid(rule-only,xxx)`（想升级但模型失败，降级）。

**成本量级**：hybrid 下绝大多数请求不产生调用；升级一次约几百 token，DeepSeek 单次几厘钱，免费额度（豆包/千问）都花不完。模型 prompt 已注入当天日期与可用站点清单，相对时间（"最近3个月"）不会算错年份。

**优先级**：环境变量 `BIDAGENT_LLM_API_KEY/BASE_URL/MODEL` > `secrets.yaml` 的 `intent.llm` > `config.yaml` 的 `intent.llm`。模型不可用/超时/JSON 解析失败（自动重试一次后仍失败）都会回退规则结果，链路不断。

离线回归：`tests/test_intent_llm.py`（14 用例，全 mock 不发真实请求）：`.venv\Scripts\python.exe -m pytest tests -v`。

## 9. 常见问题

**Q：Docker Desktop 老是自己登出账号？**

正常现象，不用管。根源是网络：Docker 登录令牌要定期向 `auth.docker.io` 刷新，这个域名在本机网络环境不可达（实测 HTTP 000），刷新失败 Desktop 就自动登出。登录在本项目里**不是必需项**：拉镜像走引擎配置的镜像源（`~/.docker/daemon.json` 的 `registry-mirrors: docker.m.daocloud.io`，实测生效），往仓库推的是代码（GitHub）不是镜像。哪天真要推镜像，用阿里云个人版或 GitHub Packages（可达），不要依赖 Docker Hub 登录。

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报`配置文件不存在` | 不在项目根目录运行 | `cd`到AI-Bid-Agent目录再`.\run.ps1` |
| 中文乱码 | 控制台编码 | run.ps1已设`PYTHONIOENCODING=utf-8`；手动跑时先设同样变量 |
| 端口8000被占 | 其他进程，或服务化常驻已在跑 | 先浏览器开`127.0.0.1:8000`试试——很可能是服务已在后台，无需再启动；真要手动跑就先`service\unregister.ps1`并停进程 |
| 重启后定时任务没了 | APScheduler不持久化（详设2.5已声明） | 重新跑一次带频率的原话即可 |
| 报`没能识别出检索关键词` | 原话全是虚词（如“帮我看一下”） | 按“时间+区域+主题+招标信息”重说 |
| 想彻底重来 | 指纹库污染 | 页面点「清空指纹」，或`POST /api/fingerprints/clear`，或删`data/bidagent.db` |
| 页面打不开（404） | `frontend/dist`未构建 | `cd frontend; npm install; npm run build`后重启`run.ps1` |
| 改了前端没生效 | 浏览器缓存或未重新构建 | 重新`npm run build`＋Ctrl+F5强刷 |
| 药丸显示「缺凭据」 | 没写`config/secrets.yaml`或字段不全 | 照第5节填`username/password/to_addrs`，重启 |
| 药丸显示「未启用」 | `push.email.enabled`为false | secrets里设`enabled: true`，重启 |
| 报`535 Authentication failed` | 填了登录密码而不是授权码，或SMTP服务没开 | 回网页邮箱重新生成授权码，确认SMTP已开启 |
| 收不到信但接口报成功 | 进垃圾箱或被反垃圾拦 | 查垃圾邮件箱，把发件地址加白名单 |
| 药丸显示「飞书群缺地址」/「钉钉群缺地址」 | webhook 地址没填到`secrets.yaml` | 照第6节填`webhook_url`（地址为空一律视为未配置，不会发包） |
| 群推送报`code=19021` / `310000` | 加签算法或时间戳不匹配；两家 key/msg 位置相反，抄错必失败 | 确认密钥填在对应平台段，校对机器时间（时间戳有效期约 1 小时） |
| 群推送报`HTTP 400`且提示关键词不合法 | 机器人安全设置只勾了「自定义关键词」 | 消息标题固定含 `AI-Bid-Agent`，把该词加进关键词白名单；或改勾「签名校验」 |
| 群推送报`HTTP 404`/`invalid webhook` | 机器人被移出群，地址失效 | 群设置里重新拿地址，替换`secrets.yaml`后重启 |
| 页面没有「重点速览」卡 | `summary.enabled=false`、无 LLM key，或模型调用失败 | 看响应 `warnings` 里的「摘要未生成：…」；再查 key 与额度（`/api/health` 的 `summary.enabled`） |
| 摘要挑的条目"不重要" | 模型判断偏差，或正文节选太少（本批部分条目只有两字） | 调小 `max_picks` 逼它只挑最强的一条；根本解法是补详情页正文抽取 |
